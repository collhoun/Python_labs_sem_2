# Лабораторная работа 4 - Асинхронный исполнитель задач

Цель работы: Научиться реализовывать приложения с асинхронной моделью управления

Постановка задачи: Реализовать асинхронный исполнитель задач, обрабатывающий задачи из очереди с использованием расширяемых обработчиков.

## Функциональные требования

- асинхронная очередь задач;
- описание контракта обработчика через Protocol;
- использование контекстных менеджеров для управления ресурсами;
- централизованное логирование и обработка ошибок;

## Технические требования

- корректное использование async / await;
- отсутствие блокирующих операций в event loop;
- архитектура, допускающая добавление новых типов задач и обработчиков;
- аннотации типов и документация;

Ожидаемый результат: Рабочая асинхронная система обработки задач, демонстрирующая архитектурную целостность и корректное использование механизмов Python.

   ```bash

   ```

## Функциональность

- **Класс `Task`** — структура для хранения идентификатора, payload и статуса задачи.
- **Источники задач**:
  - `ApiTaskSource` - эмуляция получения задач из внешнего API
  - `GeneratorTaskSource` - генерация случайных задач
  - `TextTaskSource` - чтение задач из текстового файла
- **Асинхронная очередь `TaskQueue`** — очередь задач с поддержкой асинхронных операций put и get.
- **Воркер `Worker`** — асинхронный обработчик задач из очереди.
- **Контекстный менеджер `TaskContextHandler`** — управление жизненным циклом задачи с логированием.
- **Протокол `TaskHandlerable`** — контракт для обработчиков задач.
- **Логирование** — централизованное с выводом в консоль и файл `shell.log`.
